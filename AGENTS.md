# AGENTS.md

**Read [CLAUDE.md](CLAUDE.md) first.** It is this repo's agent guide: the commands, the layout, the
code style and the git workflow live there, and it is the file kept current. Nothing on this page
repeats it — the same fact in two files is how the two start disagreeing.

This file covers one thing CLAUDE.md does not: how to ask [fallow](https://fallow.tools) a question
instead of guessing at the answer.

## The gates you are working inside

Three of them, and they run the same analysis:

| Gate | Where | Scope |
| :--- | :--- | :--- |
| `.husky/pre-commit` | human commits | `fallow audit` (new findings only) against the branch's upstream, after typecheck, lint, format and test |
| `.claude/hooks/fallow-gate.sh` | agent `git commit` / `git push` | the same audit, and `--no-verify` does not reach it |
| `.github/workflows/ci.yml` | PRs, and pushes to `development` | `fallow audit (PR gate)` with `fallow security --gate newly-reachable` on PRs; `fallow (full repo)` with the type-aware dead-code pass on `development`; `bun run check:badge` in the checks job |

So a finding you introduce blocks the commit. The point of the commands below is to answer the
question a finding raises *before* reaching for a suppression: `.fallowrc.jsonc` records a reason
for every exception it holds, and a `fallow-ignore` comment with no reason behind it will not
survive review.

## Project-specific configuration

- **`.fallowrc.jsonc`** — every entry carries a comment saying why it exists. Read it before adding
  another.
- **Architecture boundaries** are enforced: `worker` (`src/index.ts`, `src/daily-quota.ts`) may
  import `lib`, and `src/lib/**` imports nothing outside itself. That is what keeps the runtime
  (`env`, `caches.default`, the global `fetch`) out of `lib`, so every test can pass stubs.
  `fallow guard <file>` shows what applies to a file before you edit it; `fallow list --boundaries`
  prints the zones. Every file under `src/` must belong to a zone, so a new file outside them is a
  finding, not a silent exemption.
- **`usedClassMembers`** names `take` on classes that extend `DurableObject`. The Worker calls it
  over RPC through a stub (`env.DAILY_QUOTA.getByName(…).take(now)`), which the import graph cannot
  follow, so without the entry it reads as unused. A second RPC method on `DailyQuota` has to be
  added there by name.
- **CRAP is advisory here** (`maxCrap` is set out of reach). Rank with it, never gate on it — the
  tests run inside workerd and write no coverage file, so the scores are `static_estimated`, not
  coverage-backed.
- **Security candidates** are triaged in [docs/security-candidates.md](docs/security-candidates.md).
  When the PR gate's security step fails, fix the sink or add a row there.
- **The health badge** in the README is generated. If a change moves the score,
  `bun run check:badge` fails in CI; run `bun run badge` and commit the SVG.

## What fallow will not tell you

- **Who depends on the HTTP contract.** The routes, headers and error codes in
  [docs/contract.md](docs/contract.md) are used by code in other repositories: the app
  (`../diffpack`, through `VITE_DIFFPACK_PROXY_ORIGIN`) and the wasm engine (`../diffpack-engine`,
  through `set_proxy_origin`). fallow only sees this repo, so it will call an error code or a
  response header "used" or "unused" without knowing about either client. A change to the contract
  is a breaking change for both; change `docs/contract.md` first, then the code.
- **What the Workers runtime covers.** `fallow health --coverage-gaps` lists `src/index.ts` and
  `src/daily-quota.ts` as untested, because no test imports them. They are tested, through the
  runtime instead: `test/*-binding.test.ts` call the Worker's entry point through
  `exports.default.fetch`, and every proxy test counts against a real `DailyQuota` instance from
  the `DAILY_QUOTA` binding (`test/support/quota.ts`). Treat "untested" as a question, not a
  verdict.
